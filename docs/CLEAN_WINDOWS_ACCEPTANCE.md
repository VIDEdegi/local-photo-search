# クリーンWindows受入試験（未実施）

このホストにはWindows Sandbox/Hyper-V/VMware/VirtualBoxの利用可能な隔離環境を確認できなかった。機能の追加、有料サービス、ホストの再起動や共通Runtime削除は実行していない。以下は試験方法であり、成功記録ではない。

## 試験環境

Windows 11 x64の使い捨てVMで、Python/Rust/Node/Visual Studioを導入していないスナップショットを用意する。実機検証済みGPUはRTX 2070。SandboxのvGPUをRTX 2070実機と同じ性能/対応と判断しない。Windows 10 22H2 x64は別の未検証環境。

`scripts/prepare-clean-windows.ps1`で、開発版インストーラーとWindows PowerShellだけで動く検査スクリプト、online/offline.wsbをEのrelease-tests下へ用意する。自動で起動/導入しない。Sandboxが利用可能なPCで利用者がwsbを開く。入力共有は読み取り専用、書き込み共有は検証結果の専用領域だけ。モデル/写真/本番DB/ホストの開発ツールを共有しない。[Microsoft公式wsb仕様](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file)。Sandboxは閉じると消えるため、ログイン/再起動試験には通常VMが必要。

## 導入・不足Runtime・復旧

1. VMのOS build、CPU/GPU/ドライバー、空き容量、WebView2/VC Runtimeの有無を記録する。開発ツールがないことを記録する。既存Runtimeがある環境だけで不足分の試験を済ませない。
2. offlineで新規導入する。不足するVC Runtime/WebView2の名称・理由・公式取得方法が表示され、キャンセル/失敗で復旧可能なこと。旧アプリとデータがある場合、失敗後も保持されること。
3. onlineで通常のセットアップを実行。保存先選択、同意、Microsoft公式VC v14 x64導入画面、必要時だけUAC、WebView2 Bootstrapperからの導入を確認する。VCとWebView2の署名/版/容量を記録。Runtime導入後にオフラインへ切り替えてアプリ起動も確認。
4. 取得中にゲストのネット接続を切り、再試行または公式オフラインパッケージを手動導入してからセットアップ再実行で復旧すること。ウイルス対策やSmartScreenを無効化して試験しない。
5. ゲストのPowerShellで `& C:\LPS-Input\clean-windows-smoke.ps1 -InstallDirectory '実際のインストール先'`。このスクリプトは検索データ未設定の別領域、最小PATHでWorkerのenvironment/status/modelなしエラー/shutdownを確認し、C:\LPS-Resultsへ保存する。GUI起動の代替ではない。

## 初回設定・更新・データ保持

モデルがない状態で案内が開き、日本語の不足案内が出ること。公式モデルの容量/保存先/条件を表示し、**ゲスト内で利用者が明示同意したときだけ**取得する。途中キャンセル、ネット切断、途中再開、SHA不一致、空き不足、同一モデル再利用を試験。モデル462MiB取得とキャッシュ最大1GiBにはゲスト容量が必要。

既存モデルを使う別試験ではゲスト内でコピーしたものを指定する。元のホストモデルに書き込まない。任意でsmoke.ps1の`-Model 'ゲスト内のモデル'`によりCPUの小画像/テキスト診断を行える。これで実写真CPU解析の実用速度が証明されるわけではない。

人工JPEG/PNG/WebPを登録、解析、日本語/画像検索、プレビュー、元ファイル起動、保存先コピー、アプリ終了/再起動で設定と全ベクトル保持を確認する。旧0.1.1を同じVMでインストールし、モデルと人工写真を設定→完全終了→dev.2へ更新→アンインストール→再インストール。設定/登録/検索順位/ベクトルSHA/モデルSHA/旧ファイル残留/孤児Workerを各段階で記録する。ホストのQA製品名テストはこの本製品試験を置き換えない。

## バックグラウンドと障害（実マウス操作）

| 操作 | 合格条件 | この監査での状態 |
|---|---|---|
| トレイ右クリック/再表示/停止/再開/完全終了 | 各項目がマウスで選べ、状態とGPU使用が一致 | 実マウスのトレイ操作は未検証 |
| ×、背景ON/OFF | ONは格納して解析継続、OFFは完全終了 | IPC経由のONと停止再開はホスト検証。実×は別記録 |
| Windowsログイン | 既定OFF、ONにした試験VMだけRun登録、起動/非表示と状態一致 | 実ログイン未検証 |
| スリープ/復帰 | 保存済み結果保持、未処理再開、整合性ok | 未検証 |
| 再起動/アプリ強制終了 | 手動停止希望を尊重、未完了だけ再開 | 実OS再起動未検証 |
| Worker異常終了 | アプリが残り日本語案内、再起動後にベクトル保持 | ホストの隔離Worker強制終了/復旧は検証済み |
| 外付け/SMB切断、容量不足 | 既存ベクトル保持、復旧後に差分のみ | 単体/模擬試験のみ、実機未検証 |

完全終了後、対象インストール先のWorkerプロセスが残らないことをタスクマネージャーで確認する。共有を閉じる前に結果を保存。公開可否はこの試験と配布条件のゲート解決後に評価する。
