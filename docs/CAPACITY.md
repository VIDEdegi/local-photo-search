# 容量と導入依存関係

現行dev.2（2026-10-10）: installer 34,129,734 bytes（32.55MiB）、Worker 103,995,732 bytes（99.18MiB）、exe 10,099,200 bytes（9.63MiB）、通知 2,979,444 bytes（2.84MiB）。公式CPython 3.14.8の取得15,554,015 bytes、base展開41,662,246 bytesをE側へ別置き。既存固定第三者パッケージを再利用する仮想環境もE側。旧環境/実モデル/ユーザーデータは保持。合成10万件DB+WAL831,208,528 bytes。終了時の空きC約63.89GiB、E約1.13TiB。[検証結果](RC_AUDIT_RESULTS.md)と[ファイル単位一覧](DISTRIBUTION_FILES_CURRENT.md)参照。以下は旧版の履歴。

以下の表は2026-10-10のv0.1.0導入時の履歴。v1開発版の新計測は末尾に分けて記録する。ファイルの論理サイズ（実際のディスク割り当て量とは異なる）。保存先はすべてEのプロジェクト下。Downloadsにあるコピー元モデルはこの表に含めない。

インストーラーは 31.18 MiB。モデルは484,622,336 bytes（462.17 MiB）、コピー元と一致。toolsの約3.64 GiBにはダウンロード済みパッケージの再利用キャッシュも含む。

AI処理後は別途コンパイル済みキャッシュが増える。GPUのみ約298 MiB、CPU/GPU両方で約670 MiBを観測。AI処理完了・モデル切替・起動時に1 GiBを目標に整理し、現モデル分が超過した場合は解放後にキャッシュ保存なしへ切り替える。設定から削除可能。キャッシュ生成中の一時的な増加を厳密に制限する機構はSDKにない。読み込み前に768 MiBの空きを確認する。サムネイルは512 MiB上限。SQLiteは写真1枚あたり768次元float32でベクトル約3 KiBに加えメタデータ等が必要。

検証時にモデル隣へ作られたSDKキャッシュ約667 MiBは、アプリが生成した該当ファイルだけを削除し、モデルのSHA-256一致を再確認した。プローブも専用一時キャッシュを使う方式に修正。アプリ用・検証用にモデル本体を再コピーしない。

専用venv: litert-lm-api 0.18.0、Pillow 12.3.0、PyInstaller 6.22.3、およびrequirements-lock記載の小規模依存。TensorFlow本体、PyTorch、CUDA Toolkit、新しいAIモデル、FFmpegは導入していない。既存Node/Python/ドライバーを利用し、グローバル環境を置換しない。フルVisual Studio Build Toolsは導入していない。

`dist-worker`と`app/worker`は配布前の成果物とインストール済みアプリとしてそれぞれ存在する。実行時にモデルやWorkerを毎回展開・複製する方式ではない。開発環境を削除しなくても利用でき、今回個人ファイルや既存環境の整理は行っていない。

## v1.0.0-dev.1の追加計測

最終インストーラー32,825,253 bytes（31.30 MiB）、同梱Worker101.01 MiB、exe9.63 MiB、通知2.44 MiB。モデル本体462.17 MiBと既存AIキャッシュ298.17 MiBは元の領域を保持している。モデルは同梱しない。保存先にはモデル/最大1GiB AI/最大512MiBサムネイル/DBを見込み、2GiB以上の空きを推奨する（原写真は別）。モデル取得はファイルサイズ+1GiB、コピー移行は対象総量+256MiBの余裕を事前確認する。増え続ける写真件数に対する恒久的な空き容量保証ではない。

合成10万件SQLite+WALは836,244,552 bytes（797.50 MiB）。隔離release-tests全体は約1.65 GiBを観測し、テストのDB/合成写真/試験キャッシュ/QA成果物を含む開発用領域であり配布しない。テストは引き続きE側。最終空きはC約64.7GiB、E約1.14TiB。開発ツールの大型追加導入やモデルの新規取得はしていない。
