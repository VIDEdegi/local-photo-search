# v1.0リリース監査と開発計画

2026-10-10開始。基準コミット `7365489`（v0.1.1）。正式公開・Pushは禁止。全要件を満たすまでrc/正式版と呼ばない。

最終整理の追補: 現在は **1.0.0-dev.2**。下記のdev.1時点の表は開発履歴として保持する。後続の実装・検証は [RC監査結果](RC_AUDIT_RESULTS.md)、最新の通知補完・配布条件は [最終整理結果](FINALIZATION_RESULTS.md) と [DISTRIBUTION_CLOSURE](DISTRIBUTION_CLOSURE.md) を参照。公開条件未確定のまま写真成果を保存し、[音声検索の隔離開発](AUDIO_SEARCH_HANDOFF.md) に引き継ぐ。

## 保護と作業領域

E側の既存リポジトリを継続する。開始時は変更なし。C空き約65 GiB、E約1.14 TiB。モデル、SQLite/WAL、登録フォルダー、ベクトル、キャッシュを初期化しない。実データは読み取り専用の監査/少数の回帰測定だけ。試験は `data/release-tests/` またはE側tmpの専用領域。元写真は読取のみ。システムのスリープ/再起動や実ドライブ切断はユーザー作業を中断するため自動実施せず、未検証として記録する。

## 文書とコードの不一致

README/ARCHITECTUREは常駐なし・手動移行として正しいが今回更新が必要。VALIDATION表題/実写真未検証はv0.1.0時点で、PERFORMANCE_AND_CACHEの512件検証を参照すべき。CAPACITYのインストーラー31.18MiBも0.1.0時点。v0.1.1の155.46秒/512ベクトル一致は既存記録とし、新しい実測で上書きしない。

## 実装順序と依存関係

1. 監査・保護スナップショット・計画をコミット。
2. Workerの設定/環境診断/モデル取得/安全な移行と初回案内。既存configを拡張し旧設定を保持。
3. Tauriプロセスをトレイ所有者として維持。単一Worker・Job Object・stdin IPCを継続し、閉じる場合はウィンドウを隠す。独立サービス化はIPC認証/複数writer/更新管理を増やすため採用しない。
4. UI/ヘルプ/エラー/設定と利用者向け資料。
5. 隔離回帰、ビルド、実WebView2、インストーラー更新、性能/容量/ライセンス監査。
6. 配布ゲートを判定。未検証の重大項目が残れば開発プレビューとして保存し、`v1.0.0-rc.1`を作らない。

## 主なリスクとリリースゲート

- native GPUクラッシュはPython例外で捕捉不能。親は生存して再起動を案内し、Job Objectで孤児を防止する。
- モデル変更は別プロファイル。同一モデル更新で再取得/全再解析しない。公式SHAと一致しない既存モデルは勝手に置換しない。
- 移行は元を残すコピー方式。解析/ダウンロード停止、容量事前確認、DB整合性とコピーSHA検証、最後に保存先ポインター切替。環境変数指定時はポインターを変更しない。
- Windowsスリープ/実再起動/SMB切断/別GPU/開発ツールなしのクリーン環境は実測と模擬試験を区別する。
- native DLLのライセンス不明、重大な脆弱性、クリーン配布失敗は一般公開の阻害要因。
- 検証していない対応環境、精度、件数は対応済みと表示しない。
